## Urgent returning-session reliability repair

Reproduced the reported `net::ERR_FAILED` with the exact a090816 fetch/cache logic and a production-style 308 redirect from `/index.html` to `/`. The stored shell had `redirected === true`. Returning navigation failed while an isolated fresh context still opened. Previous local servers did not model Pages' HTML canonicalisation; therefore their passing offline tests missed this defect. Cloudflare's documented serving behaviour corroborates the test condition: https://developers.cloudflare.com/pages/configuration/serving-pages/ . This is an evidence-supported explanation for Chrome's fresh-versus-returning symptoms. Internet Browser's exact package/engine and device logs are unavailable, so the same cause remains plausible, not independently proven for that browser.

The worker fetches the shell from its canonical root and reconstructs any followed-redirect response before navigation. It uses a new content version including the worker generator itself. Installation completes essential files before automatic activation, so recovery can occur through the browser's service-worker update even when the old page cannot start JavaScript. Existing tabs are not forcibly reloaded. Previous caches are retained for their hashed assets; no user content is accessed by the worker. Cache read/write faults fall back to the network, successful HTTP responses survive cache-write failure, failed/non-asset responses are not cached, and missing offline navigation returns an explanatory page instead of a rejected FetchEvent.

A small boot entry registers the worker independently of the main application chunk and exposes a bounded, manual retry screen if that chunk fails. No reload loop or storage reset is used. The browser database name, version, store, document IDs and recording/backup formats are unchanged. Invalidated database connections reopen on the next operation; blocked/unresponsive opening has a bounded error. Successful saves remember only the workspace ID and reading position in local settings; saved projects are reopened after reinitialisation without overwriting newly typed work. Hidden/pagehide events save pending edits. No continuous background execution is promised.

PDF playback controls now use the final selected line's measured text endpoint and search nearby clear space against actual text rectangles and other controls. A thin association line is shown when displacement is necessary. A crowded page can fall back to its nearest clear outside margin; the right edge is no longer the unconditional default. Highlights and saved anchors remain independent of these control positions. Ordinary document controls are unchanged. Cards, recording panels, export dialogues and recipient counts use singular/plural recording wording.

## PDF passage navigation and duration correction

The editor and standalone reader previously navigated PDF recordings to the entire `.pdf-page` element, with no reference to the selected line rectangles. Thus page-centering could scroll arbitrarily relative to the actual passage, and an already-visible page could appear to do nothing. Highlights did not carry their recording's ID. The shared renderer now gives every highlight its stable annotation ID. A shared navigation function resolves the saved anchor, identifies that recording's line overlays, scrolls the actual passage through nested containers only when outside the usable view, and emphasises only those lines and its marker in purple for 2.6 seconds. Normal highlights remain. PDF page selection is synchronised; the mobile index closes to reveal the passage. Existing quote/offset and region-only anchors remain usable without storage migration or audio rewriting.

Playback placement first checks clear space at the final selected line. If the large control cannot fit, a compact control searches nearby space at or below that ending, against text and other markers. Dense paragraphs can use a compact aligned gutter marker. It no longer searches arbitrary space above a passage or generates connector lines through headings. Normal-document inline controls are unchanged.

Native audio controls previously used preload=none, so their total could remain 0:00 until metadata loaded; MediaRecorder containers may also have NaN/Infinity duration. Native totals are read-only. A shared accessible player now displays the reliable stored recording duration until finite metadata is available, then updates on media events. Unknown totals use a dash, not a false zero. Play/pause, seek, current time, error feedback and single-recording playback remain available. Native audio elements and original encoded audio are retained. No media conversion or document-data changes were introduced.
